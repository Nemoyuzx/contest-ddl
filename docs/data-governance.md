# 数据治理

## 基本原则

1. **缺失不猜测**：页面没有明确日期就不补“往年时间”；没有任何关键日期的记录不进入正式数据集。
2. **证据可追溯**：每条记录至少保存来源名称、URL、类型、权威等级、核验时间与支持字段。
3. **发现与确认分离**：赛氪和赛事目录负责发现；官方 API、主办方通知和学校官网优先，目录中的旧日期不作为证据。
4. **历史不物理删除**：来源短暂故障、列表下架或活动结束都不能让记录从仓库消失。
5. **自动化可审计**：来源故障、日期冲突、校验拒绝和人工覆盖均输出机器可读报告。

## 来源优先级

| 权威值 | 类型 | 例子 |
| --- | --- | --- |
| 5 | 官方 API / 官方平台 / 有来源的维护者核验 | MLH、赛事官网通知、人工核验 |
| 4 | 高质量社区数据库 | CS-BAOYAN |
| 3 | 经验证的二级来源 | 预留 |
| 2 | 聚合平台 | 赛氪公开页 |
| 1 | 未验证发现 | 不直接进入正式数据集 |

同一事件首先采用更高权威来源，低权威来源只能补空字段。独立来源出现不同日期时不自动“投票平均”，而是保留优先值并把冲突写入 `quality-report.json`。

## 去重

- URL：统一移动/桌面域名、移除 fragment 和常见跟踪参数、规范尾斜杠。
- 标题：NFKC 归一化，移除空格、标点和平台 SEO 后缀。
- 身份：规范标题 + 事件类型 + 届次年份。跨年份同名赛事不会合并。
- 赛氪：URL 与标题双重去重；培训、咨询、考研、留学和扫码推广在入选前过滤。
- 黑客松：各来源先独立发现，再全局合并；MLH 的平台事件 ID 是稳定身份。

## 时间线校验

- 所有时间必须可解析且带时区。
- `competition_end < competition_start` 时丢弃错误的结束字段并记录校验错误。
- `registration_deadline < registration_start` 时丢弃不可信的报名开始字段。
- 无报名、提交或比赛关键日期的记录不发布。
- 聚合站从正文提取日期时只接受附近有“报名截止 / 比赛时间 / 提交截止”标签的日期。
- 官网通用抓取器不接受新闻发布日期、更新时间、孤立日期或目录里的硬编码 DDL；无法明确归类就留空。

## 生命周期

| 条件 | 行为 |
| --- | --- |
| 本轮重新观测 | 更新 `last_seen_at`，清除 stale/archive |
| 7 天未观测 | `stale: true`，网站默认仍可按历史开关查看 |
| 30 天未观测 | `archived: true`，网站默认隐藏，JSON 保留 |
| 来源整轮失败 | 保留上一版该来源数据，不清空 |
| 活动结束 | `status: ended`，不删除 |

## 人工更正

`data/overrides.yml` 按事件 ID 覆盖自动字段。每个更正应包含 `source_url` 和 `checked_at`；更正会成为权威值 5 的新证据，并记录在质量报告的 `overrides_applied`。
